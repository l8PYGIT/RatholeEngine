# وب‌سایت مستندات (Wiki Web) — انتخاب پلتفرم و راه‌اندازی

این صفحه توضیح می‌دهد مستندات RatholeEngine چگونه به یک **وب‌سایت استاتیک** تبدیل می‌شود،
چه پلتفرم‌هایی برای این کار مناسب‌اند (از جمله چیزی که **مرزبان** استفاده می‌کند)، و چطور می‌توانی
سایت را بسازی، پیش‌نمایش بگیری و منتشر کنی.

> مستندات این پروژه سه لایه دارد:
> 1. **GitHub Wiki** (`docs/wiki/`) — دانشِ سریع، فارسی، با لینک‌های `](Page)`.
> 2. **وب‌سایت مستندات** (همین سایت) — نسخه‌ی یکپارچه‌ی `docs/` + ویکی + نسخه‌ی انگلیسی، جستجو، تم روشن/تاریک.
> 3. **README/CHANGELOG** در ریشه‌ی مخزن — برای صفحه‌ی اول گیت‌هاب و Releaseها.

---

## ۱) مرزبان از چه چیزی استفاده می‌کند؟

سایت مستندات مرزبان (`gozargah.github.io/marzban`) با **VitePress** ساخته شده است — یک تولیدکننده‌ی
سایت استاتیک مبتنی بر Vue/Vite. نشانه‌های آن در خروجی سایت دیده می‌شود (`#VPContent`، دکمهٔ
Appearance، جستجوی `K`، پیوندهای `English/فارسی/Русский`). پس اگر بخواهی «عیناً مثل مرزبان»
باشد، VitePress انتخاب اول است.

برای این مخزن اما **MkDocs Material** انتخاب شد، چون:

- پروژه از قبل **Python** دارد (`hub.py`, `ratholeagent.py`, `tools/`) و بیلد در همان محیط venv انجام می‌شود؛
  هیچ زنجیره‌ی `node_modules` به مخزن اضافه نمی‌شود.
- خروجی **کاملاً استاتیک و آفلاین** است؛ فونت/آیکون از CDN نمی‌آید (برای کاربر داخل ایران مهم است).
- جستجوی داخلی، تم روشن/تاریک، پشتیبانی RTL و ساخت تب/آکاردئون آماده است.
- یادگیری و نگه‌داری آن برای مشارکت‌کننده‌های bash/Python ساده‌تر از Vue است.

اگر بعداً VitePress را ترجیح دادی، تبدیل تقریباً بدون تغییر محتوا ممکن است؛ چون هر دو از Markdown
تغذیه می‌شوند و فقط فایل تنظیمات و ساختار nav عوض می‌شود.

## ۲) مقایسه‌ی پلتفرم‌ها

| پلتفرم | فناوری | بیلد لازم؟ | RTL/فارسی | جستجو | مناسب برای |
|---|---|---|---|---|---|
| **MkDocs Material** | Python | بله (ثانیه‌ای) | ✅ عالی (`language: fa`) | ✅ داخلی (offline) | مستندات فنی، پروژه‌های Python/bash — **انتخاب این پروژه** |
| **VitePress** | Node/Vue | بله | ✅ (لوکال‌های `fa`) | ✅ | سایت مدرن و سریع — **همان چیزی که مرزبان دارد** |
| **Docusaurus** | Node/React | بله | ✅ i18n قوی | ✅ | مستندات چندزبانه‌ی بزرگ با نسخه‌بندی |
| **Astro Starlight** | Node/Astro | بله | ✅ | ✅ | سایت سریع و سبک، ترکیب با صفحات دلخواه |
| **Docsify** | فقط JS در مرورگر | ❌ (فایل MD را همان‌جا رندر می‌کند) | ✅ | ✅ | ویکی سریع بدون بیلد؛ SEO ضعیف‌تر |
| **GitBook / Notion (SaaS)** | میزبانی‌شده | ❌ | ✅ | ✅ | تیم‌های غیرفنی؛ وابسته به سرویس ابری |
| **GitHub Wiki** | خود گیت‌هاب | ❌ | ✅ | ضعیف | مرجع سریع کنار کد — لایهٔ فعلی ویکی |

نکته‌ی مهم برای مخاطب ایران: هر گزینه‌ای که انتخاب می‌کنی، **همه‌ی assetها را محلی نگه دار**
(فونت، آیکون، JS). Material با `theme.font: false` و Docsify/VitePress بدون CDN هم قابل تنظیم‌اند.

## ۳) ساخت سایت در این مخزن

فایل تنظیمات در ریشه‌ی مخزن است: [`mkdocs.yml`](../mkdocs.yml)
(منبع محتوا `docs/`، خروجی `site/`). صفحه‌ی اول: [`docs/index.md`](index.md).

```bash
# ۱) محیط بیلد (یک‌بار)
python -m venv scratch/venv
scratch/venv/Scripts/python.exe -m pip install mkdocs-material    # روی لینوکس: scratch/venv/bin/python

# ۲) بیلد
scratch/venv/Scripts/python.exe -m mkdocs build -f mkdocs.yml     # → site/

# ۳) پیش‌نمایش محلی
scratch/venv/Scripts/python.exe -m mkdocs serve -f mkdocs.yml -a 127.0.0.1:8090
#   یا سرو خروجی استاتیک:  python -m http.server 8090 -d site
```

نکته‌ها:

- لینک‌های ویکی‌ای `](Home)` در `docs/wiki/` برای گیت‌هاب‌ویکی هستند؛ هنگام بیلد،
  [`tools/mkdocs_wiki_links.py`](../tools/mkdocs_wiki_links.py) آن‌ها را به مسیرهای واقعی سایت
  و لینک‌های خارج از `docs/` (مثل `../README.md`) را به URLهای GitHub تبدیل می‌کند.
- Mermaidها به‌صورت بلوک کد نمایش داده می‌شوند؛ SVGهای `docs/assets/` مستقیم نمایش داده می‌شوند.
- خروجی `site/` در `.gitignore` است و نباید کامیت شود (هر بار از منبع بیلد می‌شود).

## ۴) اسکرین‌شات‌ها

اسکرین‌شات‌های هاب در `docs/assets/screenshots/` هستند (داشبورد، صفحه‌ی ایران، صفحه‌ی نود،
کنترل سرویس‌ها، نقشه‌ی مسیرها، تنظیمات). این‌ها از **حالت mock** گرفته می‌شوند تا هیچ داده‌ی
واقعی/توکن روی سایت نرود:

```bash
# روی ویندوز (PowerShell):
$env:RATHOLEHUB_MOCK="1"; $env:RATHOLEHUB_CONF="mock-conf.json"; $env:RATHOLEHUB_INV="mock-inv.json"
python rathole-manager/ratholehub/hub.py        # http://127.0.0.1:8088  (رمز: admin)
```

سپس با ابزار مرورگر (مثلاً `agent-browser`) از مسیرهای `#/dashboard`، `#/server/<name>`،
`#/routing` و `#/settings` عکس بگیر و در همان پوشه بگذار. برای اسکرین‌شات جدید، فقط فایل را جایگزین کن؛
سایت و ویکی هر دو به همین نام‌ها اشاره می‌کنند.

## ۵) انتشار (Deploy)

| گزینه | مزیت | نکته |
|---|---|---|
| **GitHub Pages** (`gh-pages`) | رایگان، خودکار با Actions | این مخزن: **<https://l8pygit.github.io/RatholeEngine/>** — workflow: `.github/workflows/docs.yml` |
| **Cloudflare Pages** | سریع، خودکار از مخزن | در ایران ممکن است کند/محدود شود؛ دامنه‌ی اختصاصی + کش کمک می‌کند |
| **Netlify / Vercel** | ساده | مثل بالا، دسترسی از ایران متغیر است |
| **روی همان سرور ایران، پشت nginx** | همان دامنه/گواهی فعلی، بدون سرویس جدید | مناسب‌ترین برای مخاطب ایران؛ خروجی استاتیک را در مسیری مثل `/docs/` سرو کن و `site_url` را با همان زیرمسیر تنظیم کن |
| **بسته‌ی آفلاین** | همیشه در دسترس | `site/` را در Release یا bundle بگذار تا با `python -m http.server` محلی باز شود |

نمونه‌ی nginx برای سرو استاتیک زیر همان دامنه (فقط اگر سرویس دیگری روی `/docs` نداری):

```nginx
location ^~ /docs/ {
    alias /var/www/rathole-docs/;
    try_files $uri $uri/ /docs/index.html;
}
```

برای GitHub Pages یک workflow کوتاه کافی است (بیلد با venv و آپلود `site/` به‌عنوان artifact)؛
چون بیلد وابسته به pip است، از `actions/setup-python` و `pip install mkdocs-material` استفاده کن.

## ۶) جمع‌بندی

- برای این پروژه: **MkDocs Material** — ساده، آفلاین، Python-native، RTL و جستجوی آماده.
- اگر «عیناً مثل مرزبان» می‌خواهی: **VitePress** (Vue) — همان تجربه‌ی سایت مرزبان؛ محتوا همان Markdown می‌ماند.
- برای یک ویکی سبک بدون بیلد: **Docsify**؛ برای مستندات چندزبانه‌ی بزرگ: **Docusaurus**.
